Chapter 05 · Anvil Engine

A million tokens,
on one card.

The bottleneck was never parameters. It was the key–value cache. At a million tokens an FP16 cache demands 88.4 GB — two datacentre GPUs. TurboQuant rotates the vectors with a Fast Walsh–Hadamard transform, quantizes the residual with QJL, and the same context fits in 12.4 GB.

Open the KV playground → Read the paper ↗

TurboQuant, QJL and PolarQuant are Google Research algorithms — Zandieh, Daliri, Hadian & Mirrokni, ICLR 2026. Anvil integrates them; it did not invent them.

Index 04 · the runtime

Forge anything.

Anvil is a terminal-first local AI engine. One binary, zero runtime dependencies, no background daemon. Pure in-process inference with TurboQuant KV compression and speculative decoding built in.

C++ · MITSINGLE BINARYv0.8.6★ 8
Install & run

Two commands.
No daemon.

Anvil auto-detects CPU, GPU and RAM, configures the optimal backend, pulls GGUF directly from Ollama and Hugging Face with resumable downloads, and remembers per-model profiles across runs.

✓ ZERO TELEMETRY · no hidden blob storage · runs only when you tell it to

ANVIL · QUICKSTART
# Install
curl -fsSL https://anvil-llm.github.io/anvil/install.sh | sh

# Run a local model
anvil run model.gguf

# Pull and run from Ollama
anvil pull ollama:llama3.2:3b
anvil run llama3.2:3b

# Maximum performance: TurboQuant + MTP
anvil run model.gguf --ctx 128000 \

anvil run llama3.2 --temp 0.9 --save
